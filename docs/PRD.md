# Invoice Web MVP PRD

## 🎯 핵심 정보

**목적**: Notion에서 관리하는 견적서를 클라이언트가 웹에서 확인하고 PDF로 다운로드할 수 있는 공개 인보이스 플랫폼
**사용자**: 프리랜서/소상공인(견적서 발행자) 및 그들의 클라이언트(견적서 확인자)

---

## 🚶 사용자 여정

```
1. 클라이언트가 견적서 링크 받음 (이메일, 메시지 등)
   ↓ 링크 클릭

2. 인보이스 열기 페이지
   ↓ [링크 유효성 확인]

   [유효한 ID] → 3. 인보이스 상세 페이지
   [잘못된/없는 ID] → 에러 표시 후 홈으로
   ↓

3. 인보이스 상세 페이지
   (고객명, 상품/서비스 목록, 금액, 기한 등 표시)
   ↓ [사용자 선택]

   [PDF 다운로드 클릭] → 4. PDF 생성 및 다운로드
   [다른 인보이스 보기] → 5. 검색/목록 페이지 (MVP 이후)
   [돌아가기] → 홈 페이지
   ↓

4. PDF 생성 및 다운로드
   (현재 인보이스를 PDF로 변환)
   ↓ 다운로드 완료

   → 3. 인보이스 상세 페이지로 돌아옴

5. 완료
   클라이언트가 인보이스 확인 및 다운로드 완료
```

## ⚡ 기능 명세

### 1. MVP 핵심 기능

| ID       | 기능명                | 설명                                                               | MVP 필수 이유            | 관련 페이지                     |
| -------- | --------------------- | ------------------------------------------------------------------ | ------------------------ | ------------------------------- |
| **F001** | Notion API 연동       | Notion 데이터베이스에서 견적서 데이터 실시간 조회                  | 핵심 데이터 소스         | 인보이스 상세 페이지, 홈 페이지 |
| **F002** | 인보이스 상세 조회    | 고객명, 상품/서비스, 단가, 수량, 합계, 기한, 참고사항 등 완전 표시 | 견적서 확인의 핵심 기능  | 인보이스 상세 페이지            |
| **F003** | PDF 다운로드          | 현재 인보이스를 PDF 형식으로 변환 및 다운로드                      | 오프라인 보관/인쇄 필요  | 인보이스 상세 페이지            |
| **F004** | ID 기반 인보이스 접근 | 고유한 인보이스 ID로 특정 견적서만 조회 가능                       | 데이터 보안 및 URL 공유  | 인보이스 상세 페이지            |
| **F005** | 반응형 디자인         | 모바일, 태블릿, 데스크톱에서 최적 표시                             | 다양한 환경에서의 접근성 | 모든 페이지                     |

### 2. MVP 필수 지원 기능

| ID       | 기능명         | 설명                                              | MVP 필수 이유         | 관련 페이지 |
| -------- | -------------- | ------------------------------------------------- | --------------------- | ----------- |
| **F010** | 오류 처리      | 잘못된 ID, 없는 견적서 등에 대한 에러 메시지 표시 | 사용자 경험 및 안정성 | 오류 페이지 |
| **F011** | 홈/시작 페이지 | 인보이스 링크 입력 또는 안내 페이지               | 진입점 및 기본 안내   | 홈 페이지   |

### 3. MVP 이후 기능 (제외)

- 관리자 대시보드 (발행자용 인보이스 생성/편집)
- 웹에서 인보이스 생성/편집
- 결제/송금 통합
- 인보이스 상태 추적 (승인, 거절 등)
- 이메일 자동 발송
- 다국어 지원
- 고급 필터링 및 검색
- 실시간 알림
- 서명/도장 기능

## 📱 메뉴 구조

```
🌐 Invoice Web 내비게이션

📖 공개 페이지 (비로그인)
├── 🏠 홈
│  └── 기능: F011 (인보이스 링크 안내)
├── 📄 인보이스 상세
│  └── 기능: F001, F002, F003, F004 (인보이스 조회 및 다운로드)
└── ⚠️ 오류 페이지
   └── 기능: F010 (에러 메시지 표시)
```

**주요 동작:**

- 홈 → "인보이스 ID 입력" → 상세 페이지
- 직접 링크 접근 (예: `/invoice/abc123`) → 상세 페이지
- 잘못된 ID → 오류 페이지

## 📄 페이지별 상세 기능

### 홈 페이지

> **구현 기능:** `F011` | **메뉴 위치:** 최상위 진입점

| 항목            | 내용                                                                                                                                                          |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **역할**        | 클라이언트의 첫 진입점. 인보이스 링크 안내 및 ID 입력 페이지                                                                                                  |
| **진입 경로**   | 애플리케이션 시작 시 기본 페이지 (직접 방문 또는 `invoice-web.com/` 접근)                                                                                     |
| **사용자 행동** | 1) 제공받은 링크를 클릭하거나 2) 텍스트 input에 인보이스 ID를 직접 입력 후 조회                                                                               |
| **주요 기능**   | • 인보이스 링크 설명 및 안내 텍스트<br>• 인보이스 ID 입력 필드<br>• **조회 버튼** (클릭 시 상세 페이지로 이동)<br>• 디자인: 깔끔한 카드형 레이아웃, 중앙 정렬 |
| **다음 이동**   | 유효한 ID 입력 → 인보이스 상세 페이지, 잘못된 ID → 오류 메시지 표시 (같은 페이지에서)                                                                         |

---

### 인보이스 상세 페이지

> **구현 기능:** `F001`, `F002`, `F003`, `F004` | **접근:** ID 기반 공개

| 항목            | 내용                                                                                                                                                                                                                                                                                                                                                                                                            |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **역할**        | 견적서의 모든 세부 정보를 표시하는 핵심 페이지. 클라이언트가 상세 내용 확인 및 PDF 다운로드 수행                                                                                                                                                                                                                                                                                                                |
| **진입 경로**   | 1) 홈 페이지에서 ID 입력 후 "조회" 클릭<br>2) 직접 링크 접근 (예: `/invoice/abc123`)                                                                                                                                                                                                                                                                                                                            |
| **사용자 행동** | 1) 견적서 정보 읽기<br>2) 필요시 PDF 다운로드<br>3) 다른 작업 (홈으로 돌아가기 등)                                                                                                                                                                                                                                                                                                                              |
| **주요 기능**   | • **헤더 섹션**: 인보이스 ID, 발행일, 만료일<br>• **발행자 정보**: 사업명, 연락처 (Notion에서 설정된 정보)<br>• **클라이언트 정보**: 고객명, 주소, 연락처<br>• **상품/서비스 테이블**: [항목명 \| 설명 \| 단가 \| 수량 \| 금액]<br>• **합계 영역**: 소계, 세금(VAT) 또는 할인, 총액<br>• **추가 정보**: 기한, 결제 조건, 참고사항<br>• **PDF 다운로드 버튼** (상단 또는 하단)<br>• **홈으로 버튼** (네비게이션) |
| **다음 이동**   | PDF 다운로드 → 파일 다운로드 (페이지 유지), 홈으로 → 홈 페이지                                                                                                                                                                                                                                                                                                                                                  |

---

### 오류 페이지

> **구현 기능:** `F010` | **트리거:** 유효하지 않은 ID 또는 데이터 없음

| 항목            | 내용                                                                                                                         |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| **역할**        | 에러 상황(없는 인보이스, 만료된 ID 등)을 사용자친화적으로 안내                                                               |
| **진입 경로**   | 1) 잘못된 ID로 접근<br>2) Notion 데이터 로드 실패 시 자동 표시                                                               |
| **사용자 행동** | 에러 메시지 확인 후 "홈으로 돌아가기" 또는 ID 재입력                                                                         |
| **주요 기능**   | • 에러 메시지 (예: "견적서를 찾을 수 없습니다.")<br>• 가능한 원인 설명<br>• **홈으로 버튼**<br>• 연락처 정보 (발행자 연락처) |
| **다음 이동**   | 홈으로 버튼 클릭 → 홈 페이지                                                                                                 |

## 🗄️ 데이터 모델

### Invoice (견적서)

Notion 데이터베이스에서 조회하는 테이블 구조:

| 필드           | 설명                                                                           | 타입/관계        |
| -------------- | ------------------------------------------------------------------------------ | ---------------- |
| id             | 고유 인보이스 ID (Notion page ID 또는 커스텀 ID)                               | UUID / String    |
| client_name    | 클라이언트 이름 (Notion property: `클라이언트`)                                | Text             |
| invoice_number | 인보이스 번호 (Notion property: `견적서 번호`)                                 | Title            |
| invoice_date   | 발행일 (Notion property: `발행일`)                                             | Date             |
| due_date       | 납기일/만료일 (Notion property: `유효기간`)                                    | Date             |
| items          | 상품/서비스 목록 (Notion property: `항목`, Relation → Items DB)                | → InvoiceItem.id |
| subtotal       | 소계 — Notion에 별도 필드가 없어 `total_amount`와 동일값을 사용(MVP)           | Number           |
| tax_rate       | 세율 (%) — Notion에 필드 없음, MVP에서는 항상 미설정                           | Number           |
| tax_amount     | 세금 — Notion에 필드 없음, MVP에서는 항상 미설정                               | Number           |
| total_amount   | 총액 (Notion property: `총금액`)                                               | Number           |
| status         | 상태 (Notion property: `상태`. 실제 옵션: `대기` / `발송` / `확인함` / `완료`) | Select/Status    |
| notes          | 추가 참고사항 — Notion에 필드 없음, MVP에서는 항상 미설정                      | Text             |
| business_info  | 발행자 정보 — Notion에 DB 없음. 환경 변수(`BUSINESS_*`)로 고정 관리            | Env Var          |

### InvoiceItem (인보이스 항목)

| 필드        | 설명                                                                           | 타입/관계    |
| ----------- | ------------------------------------------------------------------------------ | ------------ |
| id          | 항목 ID (Notion page ID)                                                       | UUID         |
| invoice_id  | 소속 인보이스                                                                  | → Invoice.id |
| item_name   | 상품/서비스 이름 (Notion property: `항목명`)                                   | Title        |
| description | 상세 설명 — Notion에 필드 없음, MVP에서는 항상 미설정                          | Text         |
| unit_price  | 단가 (Notion property: `단가`)                                                 | Number       |
| quantity    | 수량 (Notion property: `수량`)                                                 | Number       |
| amount      | 금액 (단가 × 수량으로 재계산 — Notion `금액` 필드는 참고만 하고 신뢰하지 않음) | Number       |
| order       | 정렬 순서 (Notion relation 배열 순서를 그대로 사용)                            | Number       |

### BusinessInfo (사업자 정보 - 선택, 환경 변수로 관리)

| 필드          | 설명        | 타입/관계 |
| ------------- | ----------- | --------- |
| id            | 사업자 ID   | UUID      |
| business_name | 사업 이름   | Text      |
| owner_name    | 대표자 이름 | Text      |
| phone         | 연락처      | Text      |
| email         | 이메일      | Text      |
| address       | 사무실 주소 | Text      |
| tax_id        | 사업자 번호 | Text      |

## 🛠️ 기술 스택 (최신 버전)

### 🎨 프론트엔드 프레임워크

- **Next.js 15.5.3** (App Router) - React 풀스택 프레임워크, Turbopack 지원
- **React 19.1.0** - UI 라이브러리 (최신 동시성 기능)
- **TypeScript 5.6+** - 타입 안전성 보장

### 🎨 스타일링 & UI

- **TailwindCSS v4** (설정파일 없는 새로운 엔진) - 유틸리티 CSS 프레임워크
- **shadcn/ui** (new-york style) - 고품질 React 컴포넌트 라이브러리
- **Lucide React 1.34+** - 아이콘 라이브러리

### 📄 PDF 생성

- **@react-pdf/renderer** 또는 **html2pdf.js** - HTML/React를 PDF로 변환
- 대안: **Puppeteer** (Server Action에서 서버사이드 PDF 생성)

### 🔗 Notion API 연동

- **@notionhq/client 2.x** 또는 순수 **Fetch API** - Notion 데이터베이스 조회
- 환경 변수: `NOTION_API_KEY`, `NOTION_DATABASE_ID`

### 🗄️ 캐싱 & 성능

- **SWR 2.x** (선택) - 데이터 페칭 및 캐싱 (SSR 또는 ISR 사용 시 불필요)
- **Next.js unstable_cache** - Server Component 데이터 캐싱

### 🚀 배포 & 호스팅

- **Vercel** - Next.js 15 최적화 배포 플랫폼
- **Environment Variables** - `.env.local`에 API 키 관리

### 📦 패키지 관리

- **npm** - 의존성 관리
- **ESLint + Prettier** - 코드 품질 및 포맷팅

### 선택사항 (MVP 이후)

- **Supabase** - 데이터베이스 필요 시 (인보이스 접근 로그, 다운로드 횟수 추적 등)
- **SendGrid** / **Resend** - 이메일 발송 (MVP 이후 기능)

## 📌 주요 주의사항

1. **Notion API 보안**: `NOTION_API_KEY`는 Server Component 또는 Server Action에서만 사용. 클라이언트에 노출 금지.
2. **공개 인보이스**: 이 MVP는 "링크를 아는 사람 누구나" 확인 가능한 구조. 추가 보안(비밀번호 등)은 MVP 이후 추가.
3. **PDF 생성 성능**: 서버사이드 PDF 생성이 권장됨 (클라이언트사이드는 느릴 수 있음).
4. **반응형 테스트**: 모바일 환경에서의 테이블 레이아웃 특히 주의 (스크롤 또는 축소 필요).
5. **Notion 데이터 구조**: Notion DB의 정확한 필드명 및 타입을 개발 전 확인 필수.
